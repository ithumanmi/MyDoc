# Mode: Postmortem

**Job:** Blameless learning after a milestone/ship/incident so the *next* project improves.  
**Not:** Performance review; not pitch rewrite; not public marketing postmortem unless asked.

Template: `domains/game-dev/game-design/templates/game-postmortem.md`

## Required sections

1. **Context** — Project, dates, team size, goal of period, outcome (ship / cancel / pivot).
2. **Facts timeline** — Neutral events; separate later from interpretation.
3. **What went well** — Mechanisms that worked (process + design + tech).
4. **What went poorly** — Mechanisms that failed; impact.
5. **Root causes** — Systems/process causes (5 Whys lite); avoid single villain narrative.
6. **Lessons** — Portable rules (“If X, then we will Y”).
7. **Actions** — Owner · due · success check; keep ≤7 near‑term.
8. **Appendix** — Metrics if real; links to pitch/GDD/diff.

## Quality bar

| Do | Don’t |
| --- | --- |
| Separate fact vs interpretation | Invent metrics |
| Write transferable lessons | Vent without actions |
| Include wins | Only failure catalog |
| Blameless language | Name‑and‑shame |
