# Mode: Playtest / review checklist

**Job:** Plan a playtest **or** score a build review with actionable follow‑ups.  
**Not:** Permanent GDD; not teardown of competitor unless comparative section asked.

Template: `domains/game-dev/game-design/templates/game-playtest-review.md`

## Two sub‑modes (pick one or both in one doc)

| Sub | When |
| --- | --- |
| **Playtest protocol** | Before/during a session — goals, tasks, survey, telemetry |
| **Build review checklist** | Stakeholder/pass‑fail review of a build |

Align questions with `playtest-framework.md` and scoring categories in `checklist-game-review.md` / `game-review-checklist.md`.

## Required sections

1. **Meta** — Build version, date, facilitator, persona, N players (or reviewer role).
2. **Goal & success criteria** — One primary question the playtest/review must answer.
3. **Protocol** — Tasks, timebox, observation notes template (if playtest).
4. **Telemetry / metrics pack** — Events + what “good” looks like `(TBD)` ok.
5. **Survey** — 4–8 items max + 1 open memory question.
6. **Review scores** — Use 9‑area style from checklist (Feel, Core, Art/UI, Flow, Progression, Misc, LiveOps, Competitors, Business) — N/A allowed.
7. **Insights** — Tag Loop / Economy / Narrative / UX / Tech; severity.
8. **Actions** — Owner · priority · due; link to GDD section to update.

## Quality bar

| Do | Don’t |
| --- | --- |
| One primary research question | Test “everything” |
| Scores → actions | Scores with no owners |
| Note sample bias | Fake statistical significance on N=3 |
| Update GDD after synthesis | Leave findings only in chat |
