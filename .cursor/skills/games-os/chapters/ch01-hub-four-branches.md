# Chapter 1: Hub & four branches

## Core Idea
Games OS is an umbrella by **purpose** (Make/Play/Earn/Follow), not a dump of all game content into one tech domain.

## Frameworks Introduced
- **Four Branches**: Route by question — build? earn? play well? what happened this week?
  - When to use: Any “game” ask in Docs
  - How: Map to branch → open that hub only
- **Pointer Hub**: IA + map + playbook here; deep content stays where it matures
  - When to use: Tempted to paste Unity notes into `05-games-os`
  - How: Link out; keep leisure/news local

## Key Concepts
- **Make**: Design/ship tech track (`domains/game-dev`, challenges)
- **Earn**: Career/monetization (`guides/03-career-skills/game-dev`)
- **Play**: Leisure systems under `play/`
- **Follow**: Structured news under `follow/`
- **Ranh giới**: What lives here vs domains/career/`personal/`

## Mental Models
- Use Health OS pattern: hub → map → playbook → systems.
- Prefer one branch answer over “cover everything game.”

## Anti-patterns
- **Stuff play/news into game-dev**: Breaks Stable tech track maturity.
- **Clone career playbooks into hub**: Duplicate Earn; link instead.

## Worked Example
Ask: “Tin Steam charts tuần này + làm sao chơi đừng burnout?”  
Split: Follow → `follow/industry-radar` + brief; Play → `gaming-as-leisure` — không mở `domains/game-dev` trừ khi họ hỏi build.

## Key Takeaways
1. Start at `guides/05-games-os/README.md` then map.
2. Cite paths; never invent game-dev modules for leisure.
3. Adjacent life: fun-maxing, high-quality leisure, dopamine.
