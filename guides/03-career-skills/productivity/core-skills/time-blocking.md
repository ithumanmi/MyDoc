 # 📅 Time Blocking Mastery

> [← Back to Productivity](../../../README.md) | [Time Management Systems](./time-management-systems.md) | [Personal Work Framework](./personal-work-framework.md)

Time blocking biến lịch của bạn thành “bản thiết kế năng lượng” thay vì chỉ là nơi lưu họp. Bài viết này giúp bạn xây dựng hệ thống time block thực chiến: từ nguyên tắc nền tảng đến template tuần, troubleshooting và tool stack.

---

## 🎯 Vì sao nên time block?

| Vấn đề thường gặp | Time blocking giải quyết thế nào? |
|-------------------|-----------------------------------|
| To-do list dài vô tận, khó chọn việc | Ép mọi việc phải chiếm slot trên calendar → buộc ưu tiên |
| Bị kéo vào họp, chat, việc vặt cả ngày | Khóa “Deep Block” & “Shallow Block” cố định chóng nhiễu |
| Không đo được mình dùng thời gian ra sao | Lịch trở thành log: nhìn lại 1 tuần là biết đã làm gì |
| Burnout vì làm liên tục | Time block gồm cả nghỉ, recharge → nhịp sustainable |

> Key mindset: “Nếu nó không nằm trên lịch, nó sẽ không xảy ra.”

---

## 🧱 3 nguyên tắc nền tảng

1. **Batching:** Gom các việc cùng bản chất (email, họp, review) vào 1-2 block thay vì rải rác → giảm context switching.
2. **Guardrails:** Deep work, học tập, sức khỏe phải có block định kỳ; đối xử với chúng như họp với CEO (không tự ý hủy).
3. **Feedback Loop:** Mỗi tuần review lịch → so sánh “Planned vs Actual” để điều chỉnh độ dài block, thứ tự, buffer.

## 🗓️ Blueprint tuần mẫu

### 1. **Xác định mô hình năng lượng cá nhân**
- Ghi lại 1 tuần: khung giờ nào bạn tỉnh táo nhất? Khi nào dễ buồn ngủ?
- Đồng bộ block quan trọng với “Peak Energy” (thường 9h-11h sáng).
- Khung thấp năng lượng (1-3h chiều) dành cho admin, họp.

### 2. **Thiết kế lịch tuần (template)**

```
Monday
- 08:00-09:00 Weekly Planning & Metrics Review
- 09:00-11:00 Deep Block #1 (Project A)
- 11:00-12:00 Meetings/1:1
- 13:30-15:00 Deep Block #2 (Project B)
- 15:00-16:00 Email/Slack Batch

Tuesday-Thursday
- 08:00-08:30 Daily Planning + Standup async
- 08:30-11:30 Deep Block (Core Build)
- 13:00-14:00 Customer/Stakeholder calls
- 14:00-15:00 Shallow Block (Review PRs, docs)
- 15:00-16:00 Learning/Research

Friday
- 08:00-09:00 Weekly Review & Retro
- 09:00-11:00 Deep Block (Shipping)
- 13:00-14:00 Admin/Finance
- 14:00-15:00 Buffer / Overflow
- 15:00-16:00 Planning next sprint
```

### 3. **Color coding & naming convention**
- **Deep Work (Blue):** Feature build, writing, research.
- **Meetings (Red):** Only agenda-backed sessions.
- **Shallow Ops (Grey):** Email, Slack, approvals.
- **Personal (Green):** Workout, lunch, family. Đừng bỏ qua.

## 🧪 Công thức triển khai 30 ngày

1. **Tuần 1:** Audit lịch hiện tại (Calendar + Toggl). Ghi “thời gian bị rò rỉ” (scroll mạng, họp không cần).
2. **Tuần 2:** Thiết kế template tuần + thêm block cố định (Deep/Meeting/Shallow/Personal). Chưa cần 100% tuân thủ.
3. **Tuần 3:** Bắt đầu bảo vệ block. Sử dụng “No Meeting Day” hoặc “Focus AM”.
4. **Tuần 4:** Review dữ liệu → kéo dài/thu nhỏ block, tạo buffer 30’ trước & sau họp quan trọng.

> Checklist nhắc hàng tuần:
> - [ ] Deep Blocks ≥ 3 phiên/tuần, ≥ 2h/buổi
> - [ ] Shallow Blocks gom lại ≤ 2 slot/ngày
> - [ ] Weekly Review diễn ra đúng lịch
> - [ ] Buffer ≥ 1h/ngày cho việc phát sinh

## ⚙️ Kỹ thuật nâng cao

### 1. **Dynamic Time Blocking**
- Sáng mỗi ngày: drag-drop task từ backlog vào block có sẵn (Deep vs Shallow).
- Dùng “Placeholder” block (“Deep Work – TBD”) để giữ chỗ, 8h sáng mới gắn việc cụ thể.

### 2. **Split Testing Block Length**
- Thử 90 phút vs 150 phút cho Deep Work → track output (story points, trang viết, test cases).
- Nếu >120 phút dễ tụt năng lượng, chèn break 5 phút giữa block (biến thành 2 × 60 phút).

### 3. **Time Block Stacking**
- Ghép nhiều block liên tiếp thành ritual: “Prep (15’) → Deep (120’) → Review (15’).”
- Ritual giúp chuyển trạng thái nhanh, giảm thời gian khởi động.

### 4. **Team-Level Time Blocking**
- Đồng thuận “Core Collaboration Hours” (vd: 1-4pm) để giữ buổi sáng cho Deep Work cá nhân.
- Lịch team chia sẻ màu: ai bật “Focus” → người khác hạn chế book.
- Kết hợp với [Meeting & Calendar Hygiene](./meeting-calendar-hygiene.md) để giữ lịch sạch.

### 5. **Time Block KPI**
- % Deep Work giờ/tuần ≥ 40%.
- Số lần bị phá block < 3/tuần.
- Meeting ≤ 30% tổng giờ làm.
- Thời gian log được vs thời gian plan ≥ 85%.

## 🧯 Troubleshooting Guide

| Vấn đề | Nguyên nhân khả dĩ | Cách xử lý |
|--------|--------------------|------------|
| Block Deep Work bị phá liên tục | Không có buffer, team không biết bạn đang focus | Thêm “Focus” status trên Slack, block buffer 30’ giữa các slot |
| Lịch quá cứng nhắc, không theo nổi | Over-plan, không chừa chỗ cho việc phát sinh | Chỉ plan 60-70% thời gian → còn lại cho “Firefighting” |
| Time block xong vẫn trì hoãn | Block không gắn với outcome cụ thể | Đặt tên block = output (“Ship combat prototype”) |
| Calendar rối mắt | Quá nhiều màu, block ngắn | Gom block ≥ 30 phút, dùng 3-4 màu chủ đạo |
| Không sync giữa mobile & desktop | Dùng nhiều app/lịch khác nhau | Chọn 1 calendar chính, integrate mọi tool về đó |

## Time-block incident: khi troubleshooting không đủ
Nếu bạn đã áp dụng troubleshooting ở trên mà block vẫn bị phá **> 1 lần/ngày** hoặc root cause lặp lại, hãy chuyển sang runbook incident:
- Link: [Time-Block Incident Protocol](./time-blocking-incident-protocol.md)

Checklist 5 bước (làm ngay trong ngày):
1) Dừng 30 giây: `STOP` trong block.
2) Ghi 1 reason tag (root cause chính): `Interruption` / `EnergyMismatch` / `DependencyDelay` / `Overplanning` / `ContextSwitchLeak`.
3) Chọn route trong 10 phút: `Salvage` / `Swap` / `Abort`.
4) Replan phần còn lại hoặc viết 1 next action có “Done when”.
5) Cuối ngày cập nhật Planned vs Done + chọn 1 guardrail sẽ thay đổi cho lần sau.

## 📎 Template (Notion/Google Calendar)

### A. Notion Weekly Planner (Pseudo)
```
Database: Weekly Blocks
Fields: Day, Start, End, Type (Deep/Shallow/Meeting/Personal), Objective, Status (Planned/Done/Skipped)

View 1: Calendar (Week) → Drag block
View 2: Table → Filter Type = Deep để review output
Automation: Notion API + Zapier sync block state → Google Calendar
```

### B. Google Calendar Template
1. Tạo calendar phụ “Time Blocks” (ẩn/hiện tùy nhu cầu).
2. Tạo event recurring cho block cố định (Deep, Email, Workout).
3. Dùng `Copy to…` nhân block sang ngày khác.
4. Cuối ngày, update event title với `✅`, `➡️`, `❌` để tracking (Done / Moved / Canceled).
