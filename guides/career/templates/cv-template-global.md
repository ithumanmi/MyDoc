## 🎯 Key Guidelines

### 1. **ATS Optimization**

**DO:**
- Use standard section headers (Summary, Experience, Skills, Education)
- Include keywords from job description
- Use bullet points (•) not fancy icons
- Save as `.pdf` with text (not image)
- File name: `FirstName_LastName_Backend_Developer.pdf`

**DON'T:**
- Use tables, columns, or text boxes
- Add photos (US/EU standard)
- Include personal info (Age, marital status, photo)
- Use fancy fonts or colors

---

### 2. **Action Verb + Task + Result (ATR) Formula**

**Bad:**
> "Responsible for backend development"

**Good:**
> "Architected microservices platform serving 500k+ users, reducing latency by 60%"

**Formula:**
```
[Action Verb] + [What you did] + [Quantifiable result]
```

**Action Verbs to Use:**
- Built, Architected, Designed, Implemented
- Optimized, Reduced, Improved, Increased
- Led, Mentored, Collaborated, Established
- Migrated, Integrated, Deployed, Automated

---

### 3. **Quantify Everything**

**Numbers recruiters love:**
- Users: "Serving 1M+ users"
- Performance: "Reduced latency by 60%"
- Scale: "Processing 10M requests/day"
- Cost savings: "Reduced infrastructure cost by $50k/year"
- Team: "Led team of 5 developers"
- Time: "Reduced deployment time from 2h to 15min"

**If you don't have exact numbers:**
- Estimate conservatively
- Use ranges: "50k-100k users"
- Use "+": "100k+ requests/day"

---

### 4. **Tailoring for Each Job**

**For Backend role emphasizing Performance:**
- Highlight: Optimization, caching, database tuning
- Keywords: Scalability, high-traffic, low-latency

**For Full-stack role:**
- Balance: 50% backend, 30% frontend, 20% DevOps
- Highlight: End-to-end ownership

**For Startup:**
- Emphasize: Fast learner, wore multiple hats, MVP delivery
- Show: Entrepreneurial mindset, shipped features quickly

**For Enterprise:**
- Emphasize: Best practices, documentation, testing
- Show: Experience with large teams, legacy systems

## 📊 CV Length Guidelines

| Experience Level | Pages | Focus |
|-----------------|-------|-------|
| **Junior (0-2 yrs)** | 1 page | Education, Projects, Internships |
| **Mid (3-5 yrs)** | 1-2 pages | Recent experience, Key projects |
| **Senior (5+ yrs)** | 2 pages | Leadership, Impact, Architecture |

**Rule:** If you can't fill 2 pages with MEANINGFUL content → Stick to 1 page

## 💡 Pro Tips

### Tip 1: GitHub Profile Optimization

**Make sure your GitHub shows:**
- Pinned repos (3-6 best projects)
- Good README with screenshots, demo links
- Consistent commit history (Green squares)
- Code quality (Tests, documentation, clean commits)

**What recruiters check:**
1. Can you write clean code?
2. Do you finish projects?
3. Can you document?
4. Do you contribute to open source?

---

### Tip 2: Portfolio Website (Optional but Powerful)

**Must-haves:**
- Hero: Name, Title, 1-sentence pitch
- Projects: 3-5 best works with screenshots
- Tech stack list
- Contact/Links
- Fast loading (< 2s)

**Platforms:**
- Vercel/Netlify: Deploy Next.js portfolio
- GitHub Pages: Simple HTML/CSS
- Framer: No-code beautiful sites

---

### Tip 3: LinkedIn = Extended CV

**Optimize:**
- Headline: "Senior Backend Engineer | Go, Node.js, Kubernetes | Building Scalable Systems"
- About: Expand on CV summary (3-4 paragraphs)
- Experience: Same as CV but MORE detail
- Skills: Endorse top 10 skills
- Recommendations: Ask former colleagues/managers

**Activity:**
- Post technical insights (1-2x/week)
- Comment on industry posts
- Share projects

## 🚫 Common Mistakes to Avoid

**1. Generic Summary**
❌ "Hardworking developer seeking opportunities"
✅ "Senior Backend Engineer with 5+ years building high-traffic APIs"

**2. No Metrics**
❌ "Improved system performance"
✅ "Reduced API latency by 60%, from 1.2s to 450ms"

**3. Too Technical in Summary**
❌ "Proficient in OOP, SOLID principles, design patterns..."
✅ Save technical details for Skills section

**4. Irrelevant Experience**
- If switching from non-tech → Only include last 5-7 years
- Old technologies (VB6, Flash) → Remove unless relevant

**5. Lying**
- Never lie about experience/skills
- You WILL be caught in technical interview
- Exaggerate slightly is ok, lying is not
