## 🔧 Kiến trúc Feature Store & Đánh Giá Mô Hình (thực chiến)
- **Feature store (batch + stream)**: 
  - Batch: parquet/feather, layout theo partition thời gian; point-in-time join để tránh leak. 
  - Stream: Kafka/Kinesis → online store (Redis/Feature server) phục vụ inference thấp trễ. 
  - TTL & versioning: tránh drift, cho phép rollback. 
- **Labeling**: triple-barrier, event-driven, meta-labeling để giảm false positives. 
- **Validation**: purged/embargoed CV, walk-forward; tránh overlap leakage. 
- **Metrics**: không chỉ accuracy; dùng Sharpe/Sortino, PBO, turnover, TCost, capacity. 
- **Latency-aware**: giới hạn thời gian inference; fallback rule-based nếu timeout. 
- **Model risk/rollback**: canary, shadow mode, nút kill-switch.

## ⚠️ Lưu ý khi dùng DRL/ML trong trading
- Dự báo giá trực tiếp thường vô ích nếu thị trường gần random walk; tập trung phân loại regime/rủi ro. 
- Mô phỏng slippage/fee/latency trong môi trường gym; nếu không, PnL ảo. 
- Phân rã feature importance và kiểm tra ổn định (stability) qua thời gian; loại feature “mùa vụ” nhanh hỏng. 
- Giới hạn complexity để tránh overfit; ưu tiên mô hình gọn (tree/linear) cho sản xuất thấp trễ.

## Ví dụ point-in-time join (avoid look-ahead)
```python
# features_daily: index = date, columns: ['symbol','feature1','feature2'] extracted with T-1 cutoff
# prices: index = date, columns: ['symbol','close']
# goal: join only info known at or before date t

feat = features_daily.copy()
price = prices.shift(-1)  # optional if predicting next-day return

# Ensure no forward fill beyond cutoff
feat = feat.sort_index()
price = price.sort_index()

dataset = (
    feat
    .join(price, how='inner', lsuffix='_feat', rsuffix='_target')
    .dropna()
)
```

Checklist PIT/validation:
- [ ] Lấy feature với cutoff T-1 hoặc T-Δ, không dùng dữ liệu sau thời điểm dự đoán.  
- [ ] Dùng purged/embargoed CV để tránh leak chuỗi thời gian.  
- [ ] Không forward-fill vượt qua sự kiện; dùng window cố định.  
- [ ] Log phiên bản feature/label để reproducible.
